## Operating systems, utilities and program libraries

### Why a computer requires an operating system

An operating system is the software that manages a computer's hardware and software resources and provides the interface through which users and programs use the machine. The need it answers is sharing. One machine - its processor, its RAM, its storage, its devices - is used by many programs and many users at once, and something must decide who gets what, keep them from colliding, and provide a common way in. The OS does this once, for all programs. Without it, every application would have to drive the hardware itself: allocate its own memory, command each device, handle its own files and errors, and each program would duplicate the same work badly. The OS also runs from the first moment: it starts up the hardware, loads and runs the programs, and fielded the errors that arise, so no other software can run without it, which is the plainest statement of the requirement. Its own security role sits here too: user accounts, access rights and passwords - who may log on, and what they may use - are managed by the OS itself, not by anti-virus software or a firewall, which are separate programs that run on it.

### The key management tasks

The OS's management tasks divide into five, and each has its own subject. Memory management is about RAM while programs run: it allocates each process an area of memory and protects one process's area from another, so programs run side by side without overwriting each other - the boundary to hold is RAM at run time, not files on a disk. File management is about storage: it keeps the disk's directories and files, records where each file's parts sit, and controls who may access what. Security management is about people: user accounts, access rights and passwords, deciding who may log on and what they may use. Hardware management is about devices: input, output and peripherals - the keyboard read, the printer driven, the disk positioned - each a device the OS commands for whichever program needs it. Process management is about time: the OS decides which process runs when, so several programs share the one processor, each proceeding as though it had the machine to itself. A question naming one task is answered by naming its subject - memory, files, users, devices, processor - because the subjects, not the words, are what separate the tasks.

### Utility software supplied with the OS

Around the OS's management sit the utilities, supplied with it to maintain the computer. A disk formatter prepares a new disk for use, writing the structure the file system needs. A virus checker scans storage and files for malware, quarantining what it finds. Defragmentation software rearranges the parts of files on the disk so each file sits contiguously: as files are saved, changed and deleted, one file's parts end up scattered, and the disk head travels far to read one file; defragmentation moves the parts together so the head travels less and the file reads faster - and the file's size is unchanged, because data is moved, not removed. Disk analysis and repair software checks the disk's contents and mends what it can. File compression software makes files smaller, and the making-smaller is 1.3's whole subject, with its lossy and lossless methods. Back-up software copies files to a second place for safety, which is the plainest protection a user can buy with a click. The utilities arrive with the OS because they maintain the machine the OS manages, and they are written to work with its file systems.

### Worked example: a learner double-clicks a document

A learner double-clicks a saved document, and the OS goes to work through its tasks. Process management creates a process for the word processor and gives it a turn on the processor. Memory management allocates the process an area of RAM and protects every other program's area from it. File management reads the directory to find where the document's parts sit on the disk, and reads them into the process's memory. Hardware management drives the disk, the screen and the keyboard for the process while it runs. Security management checks, at each step, that this learner's account may open this document - a shared computer keeps its marks where only the teacher's account reaches. And when the learner closes the document and clicks Save, the same tasks run in reverse: the process ends and its memory is released, the file's parts are written back to storage, and the disk is driven again. One click, five management tasks, and none of them visible to the learner - which is the point: the OS exists so that no program and no user has to do any of it. Run the same click on the office's shared computer and the security step shows its teeth: the learner's account opens the document, a colleague's account is refused, and no program had to ask - the OS asked, because access is its question to put.

### Program libraries and DLL files

Software under development is often constructed from existing code, and program libraries are where that code lives: a collection of pre-written, tested routines that a program can use. Sorting a list, handling a date, drawing a chart - these are solved problems, and a library hands the developer the solved routine instead of the blank file. The benefits are direct: the routine is already written, so development is faster; it is tested in many programs before yours, so it is reliable; and when it is mended, every program using the library gains the mend. A Dynamic Link Library (DLL) file carries the sharing further: the library is linked when the program runs, not built into the program file, so several programs share one copy of the routine instead of each carrying its own - which keeps each program file smaller, and lets one updated DLL serve every program that uses it. The same coin has its other face: a program is only as available as the library it links, so a missing or incompatible DLL stops the program from starting, which is the cost the sharing carries.

### Common errors

Three slips recur here. Describing file management for memory management: memory management is about RAM while programs run, and the test is whether the answer is about RAM at run time or files on a disk. Believing defragmentation reduces file size: it moves the parts of each file together so they read faster, and the test is whether the amount of data changes - it does not, only where it sits. And giving the OS a security job that belongs to separate programs: anti-virus software and a firewall run on the OS, while the OS's own security management covers user accounts, access rights and passwords - the test is whether the feature is part of the operating system or a program that runs on it.
