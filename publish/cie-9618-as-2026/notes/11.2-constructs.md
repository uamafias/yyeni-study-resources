## Constructs: selection and iteration

### Selection: IF, ELSE and nesting

Selection chooses between paths, and the IF statement is its full form:

```pseudocode
IF Marks >= 50 THEN
   OUTPUT "Pass"
ELSE
   OUTPUT "Resit"
ENDIF
```

The condition is tested once; the THEN branch runs when it holds, the ELSE branch when it does not, and ENDIF closes the statement. Nested IF statements test a second condition after the first - a further selection inside a branch, closed by its own ENDIF:

```pseudocode
IF Marks >= 50 THEN
   IF Marks >= 80 THEN
      OUTPUT "Distinction"
   ELSE
      OUTPUT "Pass"
   ENDIF
ELSE
   OUTPUT "Resit"
ENDIF
```

The nesting is read inwards: the outer IF splits pass from resit, and the inner IF - reached only on the pass side - splits distinction from pass, so the marks land in one of three paths. Conditions joined with AND or OR carry one rule above all: each side of AND or OR is a complete comparison, so a pass with distinction is IF Marks >= 80 AND Attendance >= 90 THEN, with both comparisons written in full - and IF Grade = "a" OR "b" is not a condition at all, because "b" standing alone is not a comparison. The test is to read each side of the OR aloud by itself: each side must stand as a condition, because an unfinished comparison selects no path at all.

### Choosing the loop: FOR, WHILE, REPEAT

The three loops are chosen by two questions, and the first is the decider. Can the number of iterations be said before the loop starts? If it can, the FOR loop is the right one - FOR Day <- 1 TO 7 runs exactly seven times, the count fixed in the loop's own line. If it cannot, no FOR belongs there: reading marks until a negative one arrives has no count to say in advance, so the loop ends on a condition instead, and the conditional loops are WHILE and REPEAT. The second question separates those two: must the body run at least once? A REPEAT ... UNTIL loop runs the body first and tests after, so the body always runs at least once - a menu must be shown before it can be answered. A WHILE loop tests before the body, so the body may run zero times - an empty file ends the reading loop before any pass. Each loop also carries a duty: the body must move the condition towards its end - the WHILE that reads must eventually read the negative mark, the REPEAT that menus must eventually receive the quitting choice - because a WHILE whose condition nothing inside changes runs forever, which is the fault the justification question usually hides.

### Worked example: one problem, three loops judged

A taxi rank’s program needs three loops, and each is judged on the two questions. Loop 1: output the twelve hours’ passenger counts in order. The count is known - twelve - so FOR Hour <- 1 TO 12 is the justified loop, because the loop’s own line states its count. Loop 2: read arrivals until the count of taxis waiting reaches zero. No count can be said in advance, and the waiting count may already be zero when the read begins - so a WHILE loop fits, tested before the body, because the body may need to run zero times on an ended day. Loop 3: show the dispatch menu and act on the controller’s choice until the choice is the quit code. The menu must be shown before any choice exists, so the body runs at least once - a REPEAT ... UNTIL Choice = 0 loop is the justified one, because its after-test matches the must-show-first shape. Three jobs, three different loops, one pair of questions, and the pair judges any loop the program meets, because the questions are about the repetition, not the job.

### Common errors

Two slips recur. One-sided conditions: IF X = "a" OR "b" is not a condition, because "b" alone is not a comparison - each side of AND or OR is written as a complete comparison, so IF X = "a" OR X = "b" is the full form. Read each side alone. And a FOR loop where the count is not known in advance: a repetition that ends on a condition cannot be a FOR, because a FOR states its count in its own line.
