## Components and devices

### Input, output, memory and storage

A computer system needs parts that answer four different needs. Input devices feed data in: the keyboard, the microphone, the touchscreen's sensing layer. Output devices present results: the screen, the speakers, the printer. Primary memory holds the running program and the data it is working on, because the processor reads memory directly while it executes. Secondary storage keeps files between sessions: the disk, the solid state drive, the memory card, all of which hold their contents when the power is off. The distinction to hold on to is memory against storage, because the words are used loosely everywhere else. Memory is primary (RAM and ROM) and is read directly by the processor while the program runs; storage is secondary and keeps files between sessions. A learner's photos are kept in storage, not in memory; a running program lives in memory, and is lost when the power goes. The test for which is which: does the processor read it directly while running? Memory. Do the files survive switch-off? Storage.

### Embedded systems

An embedded system is a computer system built into a larger device to perform a dedicated task, with its program fixed for that task: the controller in a washing machine, the timer in a microwave oven, the engine unit in a car. What makes it embedded is being part of the device and dedicated to it, not what it does - some embedded systems control things, others play music or keep time. The benefits follow from the dedication: the program is written for one job, so it runs the same way every time; the parts are few, so it is typically cheap, small, reliable and light on power. The drawbacks follow too: the fixed program is hard to change, and the system usually does its one job only - a washing machine's controller will not balance a spreadsheet, and was never meant to. A general-purpose computer is the opposite trade: expensive flexibility, one machine doing any job its software brings. Between the two sits the phone in a pocket: mostly general-purpose, but the baseband unit that talks to the cell network is an embedded system dedicated to that one job, which is why it keeps working whatever else the phone is busy with.

### The principal operations of devices

Hardware devices each do one principal thing, and naming the operation is the skill this objective asks for. Storage devices first. A magnetic hard disk records data as magnetised regions on spinning platters, and a read head detects the magnetisation as the platter passes - no laser, no pits, that is the optical disc's world. An optical disc reader works with a laser: it reads the pattern of pits and flat lands on the disc's surface, and a writer burns that pattern onto a writable disc. Solid state (flash) memory stores data as charge in electronic cells, with no moving parts, so it is silent, quick and indifferent to knocks. Output devices: a laser printer forms the page image with a laser, transfers toner to the paper and fuses it; a 3D printer builds a solid object layer by layer from a design; speakers convert electrical signals into sound. Input devices: a microphone converts sound into electrical signals - the speakers' exact opposite. And two devices that do both: a touchscreen combines display and input by sensing where it is touched, and a virtual reality headset presents an image to each eye while its sensors track the head's movement. Naming a device's operation is a two-step habit: ask what goes in or comes out, then ask what change the device makes - a pattern to apply to any device the table throws up, from a barcode reader to a projector, because every device has one principal operation and the marks go to the one that is named.

### Buffers

Devices work at different speeds, and something has to stand between them. A buffer is an area of memory that holds data temporarily while it is moved between devices or processes working at different speeds. The word to be careful with is what the buffer does: nothing. It is an area of memory, and the processor is what moves data into it and out of it - a buffer cannot act. What the buffer buys is independence of speeds. The producer fills it and carries on with other work; the consumer drains it at its own pace. Printing is the everyday case: the processor prepares a whole document far faster than any printer prints it, so the document's data is placed in a buffer and the processor is free at once, while the printer takes the pages from the buffer at its own speed. Streaming is the same arrangement with different parts: arriving bits are held in a buffer and fed to the player at the player's pace, so the network's bursts and pauses do not stop the picture.

### Worked example: a document goes to print

A teacher presses Print on a 60-page workbook, then starts marking emails on the same computer. What the buffer arrangement does, step by step. The processor writes the workbook's pages into the print buffer - an area of memory - and returns to the teacher at once; the emails open while the printer has not printed page one. The printer drains the buffer page by page at its own speed, and the processor tops the buffer up between keystrokes whenever the printer falls behind. Both speeds are respected: the processor is not throttled to the printer's pace, and the printer is not starved by the processor's distractions. If the buffer is small, the printer pauses when it empties and waits for a top-up; the larger the buffer, the more the two work independently. Nothing is sent by the buffer itself - every movement of data is the processor's work into and out of that area of memory.

### Common errors

Four slips recur here. Using memory and storage as one word: memory is primary and read directly by the running processor; storage is secondary and keeps files when power is off - the test is whether the processor reads it while running, or the files survive switch-off. Calling a device embedded because it controls something: embedded means built into a larger device for a dedicated task, and control is only one such task. Writing lasers and pits for a magnetic hard disk: a magnetic disk uses magnetised regions and a head; laser and pits belong to the optical disc - the test is whether the data is magnetic or optical. And giving the buffer the credit for sending: a buffer is an area of memory that holds data; the processor moves the data, because a buffer cannot act.

## Memory types and control systems

### RAM and ROM

Both are primary memory, and the difference is one line: RAM is the working memory, ROM is the permanent memory. RAM is read/write memory that holds the running program and its data, and its contents are lost the moment power is removed - which is why unsaved work dies with a power cut. ROM keeps its contents permanently, in normal use it is read rather than written, and it holds the start-up instructions, the code that must be there the instant power arrives, before anything can be loaded from storage. The uses follow the properties. RAM goes wherever contents change constantly: the program being run, its variables, the document being typed. ROM goes wherever contents must survive switch-on: the start-up code of a personal computer, the fixed program of a cash register, the controller of an embedded system. A device that updates its program overnight still keeps its start-up code in ROM, because the update can only arrive once the system has started - ROM is what makes starting possible. A range of devices leans on the same split: a game console keeps its boot code in ROM and its games in RAM when they run; a medical pump keeps its safety routines in ROM and the day's settings in RAM, so losing power costs the settings but never the code that keeps the pump safe.

### SRAM and DRAM

RAM itself comes in static and dynamic forms, and the difference is how each bit is kept. Static RAM (SRAM) holds each bit in a small holding circuit that keeps its value until it is rewritten; no refreshing is needed, so reads and writes complete fast, but each bit takes several transistors, so a chip holds fewer bits and each bit costs more. Dynamic RAM (DRAM) holds each bit as charge on a capacitor; the charge leaks away, so the chip continually refreshes every cell, which slows access, but each cell is one capacitor and one transistor, so capacity is cheap and dense. The choice between them is settled by what the part is for. Cache memory - the small, close store the processor reads first - uses SRAM, because speed matters more than capacity there. Main memory uses DRAM, because a running system wants capacity, and a small delay is the cheaper price. The device's use decides the RAM, which is the sentence that answers any SRAM-or-DRAM question.

### PROM, EPROM and EEPROM

Programmable ROM comes in PROM, EPROM and EEPROM, differing in how they can be rewritten. A PROM - programmable ROM - can be written once, after manufacture, and not erased: the program goes in once and stays for the device's life. An EPROM - erasable programmable ROM - can be erased by ultraviolet light shone through a quartz window on the chip, then rewritten; the chip must come out of the circuit to be erased, so the update is a bench job. An EEPROM - electrically erasable programmable ROM - is erased and rewritten electrically while still in place in the system, so a service laptop can update a device's program in the field without removing anything. Each step up the list costs more and updates more easily: the PROM is cheapest and never changes, the EPROM changes at the bench, the EEPROM changes in place - and modern devices largely take the EEPROM's convenience as standard.

### Monitoring and control systems

A monitoring system measures and reports; a control system measures, decides and acts. In a monitoring system, sensors read the environment - temperature, pressure, infra-red radiation, sound - and the values are displayed or recorded; nothing is changed by the system itself, so a weather station that logs temperatures is monitoring. The same hardware can serve both: a greenhouse's temperature sensor feeds the logger that graphs it, and the same wire feeds the control unit that opens the vents - what separates monitoring from control is not the sensor but what the system does with the reading. In a control system, the sensor values go to a microprocessor (the control unit), which compares them with the target and decides; the decision drives actuators, devices that produce physical movement or action from a signal - a motor opening a vent, a valve letting water through, a heater switching on. The parts must not be given each other's roles: the microprocessor decides, the actuator acts, and the sensor measures. The word that makes control accurate is feedback: the system's own output affecting its next input. The heater warms the room; the temperature sensor measures the warmed room; the next decision starts from the measured value, not a guess. Without feedback, a control system drives blindly and overshoots; with it, the system holds the value steady, which is why feedback is the mechanism control runs on. The sensors named in the objective each measure one quantity: a temperature sensor reads heat, a pressure sensor reads force per area, an infra-red sensor reads the radiation a warm body gives off, and a sound sensor - a microphone - reads pressure waves in the air; choosing the sensor is choosing what the system can see.

### Worked example: a borehole keeps its tank full

A village borehole system keeps a water tank full. Its parts: a water-level sensor in the tank; a control unit; a pump; and the pipes that carry the pumped water. Run one cycle. The sensor measures the tank's water level and sends the value to the control unit. The control unit compares the level with the set point - 'tank above three-quarters full'. The level is below, so the control unit decides to pump, and drives the pump, the actuator, which moves something physical: water. The tank fills. Now feedback: the rising water level is the system's own output, the sensor measures it, and the next comparison is made against the new level. When the level passes the set point, the control unit stops the pump. Two labels to place carefully: the pump is the actuator, and it acts - the decision to run it belongs to the control unit. And the system is a control system, not a monitoring one, because it changes its environment; the same sensor and control unit with a graph on a screen and no pump would be a monitoring system, measuring and recording without acting.

### Common errors

Two slips recur in control questions. Giving the microprocessor and the actuator each other's roles: the microprocessor decides, the actuator acts - the test is to ask which part moves something physical, because that part is the actuator. And reading feedback as user opinion: feedback is the system's own output affecting its next input - the test is to ask where the feedback comes from, because it comes from the system's own output through its sensors, not from any user's views.
