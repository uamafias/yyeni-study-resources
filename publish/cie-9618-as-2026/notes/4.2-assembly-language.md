## Assembly language, the assembler and tracing

### Assembly language and machine code

What the processor executes is binary: machine code is patterns of bits, one pattern per instruction, with an opcode and an operand. Writing and reading those patterns by hand is slow and error-prone, so assembly language writes the same instructions in a form a person can work with. Each instruction is written as a mnemonic - LDM for load, STO for store, CMP for compare - with symbolic addresses (labels) standing in for numeric locations. The correspondence is exact: each assembly instruction corresponds to one machine instruction, so assembly is machine code in readable clothing, and translating it is mechanical. That is the assembler's job: it translates the mnemonics into their binary opcodes and the labels into their computed addresses, producing the machine code the processor runs. The contrast with a compiler matters: a compiler translates a high-level language program as a whole, and one high-level statement typically becomes many machine instructions, whereas the assembler works instruction by instruction because its input already is one instruction per line. Hand-written assembly earns its keep where exact control of the instruction stream matters - a timing-critical port switch, for instance - because what you write is what executes, with nothing added.

### The two-pass assembler

Why two passes? Because of forward references. A jump may be written to a label defined further down the program, and when the assembler first reaches the jump, the label's address is not yet known - no single pass over the program can both compute it and use it. So the work is split. First pass: the assembler reads the program line by line without generating machine code; because each instruction's length is known, it computes the address each instruction will occupy, and it enters every label with its computed address into the symbol table - the program's address book. Second pass: the assembler reads the program again, this time generating machine code - each mnemonic becomes its opcode, and each label in an operand is replaced by the address the symbol table holds for it. A label with no entry in the table is reported as an error, because pass two has no address to write. One pass maps the program, the other writes it, and both read the same lines, which is why the assembler is called two-pass.

### Tracing a program

A trace table follows a program through the processor one executed instruction at a time. One row per instruction executed; one column per thing that changes - the accumulator, the memory locations the program uses, the flags a compare sets, any output produced. The discipline that makes a trace reliable: fill the row as the instruction finishes, take the next instruction from the program order unless the row you just wrote says a jump was taken, and record flags the moment a compare sets them, because the next conditional jump reads exactly those flags. That is the safe way through a loop: a conditional jump makes the next instruction depend on flags no one can hold in mind reliably, and the table records what the flags were, so the decision is read from the row, not guessed.

### Worked example: tracing a counting loop

Trace this program, with TOTAL a memory location:
        LDM  #0
        STO  TOTAL
LOOP:   INC  TOTAL
        LDD  TOTAL
        CMP  #3
        JPN  LOOP
        END
Row by row. LDM #0 puts 0 in the accumulator (immediate: the number itself). STO TOTAL stores it: TOTAL = 0. INC TOTAL adds 1 to the contents of TOTAL, in memory: TOTAL = 1, and note the accumulator has not changed. LDD TOTAL loads 1 into the accumulator. CMP #3 compares 1 with 3: 1 - 3 = -2, so the negative flag is set. JPN LOOP is taken, so the next instruction is INC TOTAL again, not END. Round the loop: TOTAL becomes 2, accumulator 2, compare gives -1, jump taken. Round again: TOTAL becomes 3, accumulator 3, compare gives 0, the negative flag is clear, so JPN is not taken and the next instruction is END. Final state: TOTAL = 3, accumulator = 3, and the loop body executed three times. The trace in table form, one row per executed instruction: 

| Instruction | ACC | TOTAL | Flags after | Next |
|---|---|---|---|---|
| LDM #0 | 0 | - | - | STO |
| STO TOTAL | 0 | 0 | - | INC |
| INC TOTAL | 0 | 1 | - | LDD |
| LDD TOTAL | 1 | 1 | - | CMP |
| CMP #3 | 1 | 1 | negative | JPN |
| JPN LOOP | 1 | 1 | taken | INC |
| INC TOTAL | 0 | 2 | - | LDD |
| LDD TOTAL | 2 | 2 | - | CMP |
| CMP #3 | 2 | 2 | negative | JPN |
| JPN LOOP | 2 | 2 | taken | INC |
| INC TOTAL | 0 | 3 | - | LDD |
| LDD TOTAL | 3 | 3 | - | CMP |
| CMP #3 | 3 | 3 | not negative | JPN |
| JPN LOOP | 3 | 3 | not taken | END |
| END | 3 | 3 | halt | - |

### Common errors in traces

Three slips recur in trace questions. Forgetting that INC and DEC change memory, not the accumulator: their operand is an address, and the change lands at that location, so the trace needs a memory column. Forgetting that CMP changes flags, not the accumulator: the compared value stays as it was, and only the flags move. And forgetting that a taken jump changes the next instruction: the row after a taken JPN is the jump's target, not the following line, because the program counter has been rewritten.

## Instruction groups and addressing modes

### The instruction groups

The instruction set is grouped by what the instructions do, and the groups are the syllabus's own. Data movement moves values between the accumulator and memory: LDM #n loads the number n itself into the accumulator, LDD <address> loads the contents of the given address, LDI <address> loads indirectly, LDX <address>, IX loads with indexed addressing, and STO <address> stores the accumulator's contents at the given address. Input and output: IN <address> reads a character in and stores its code at the given address, and OUT <address> outputs the character whose code is stored at the given address. Arithmetic: INC <address> adds 1 to the contents of the given address and DEC <address> subtracts 1 - both act on memory, not the accumulator. Compare: CMP <address> compares the accumulator's contents with the contents of the given address, and CMI #n compares them with the number n itself, setting the status flags either way. Jumps: JMP <address> jumps unconditionally, JPE <address> jumps if the even flag is set, JPN <address> jumps if the negative flag is set - the two conditional jumps read the flags a compare left behind, which is how a program makes a decision. END halts the program.

### The addressing modes

An addressing mode says how an instruction's operand is found. Immediate (#n): the operand is the number n itself - LDM #5 loads 5, and no memory lookup happens. Direct: the operand is the contents of the given location - LDD 200 loads whatever is stored at 200. Indirect: the given location holds an address, and the operand is at that second location - LDI 200 takes the contents of 200 as an address and loads from there, so the location holds a pointer. Indexed: the address used is the address given plus the contents of the index register - LDX 200, IX with IX holding 100 reads location 300. Relative: the address is calculated relative to the address of the current instruction, the program counter, so the program runs wherever it is loaded. A worked contrast, with memory holding: location 200 holds 42, location 42 holds 7, location 300 holds 9, IX holds 100.
LDM #200 loads the number 200 itself.
LDD 200 loads 42, the contents of 200.
LDI 200 takes 42 from 200 as an address, and loads 7, the contents of 42.
LDX 200, IX calculates 200 + 100 = 300, and loads 9, the contents of 300.
Four loads, four different results, one lesson: the mode decides where the operand comes from, and the notation - #, bare address, or IX - names the mode.

### Common errors with modes

Two slips recur. Reading a bare address as a number: LDD 200 loads the contents of location 200, and only LDM #200 loads the number 200 itself - the test is whether a # stands in front, because the # means use the number and no # means look up the location. And adding IX to the value instead of the address: indexed addressing adds the index register to the address given, then uses the contents of that calculated address - the test is add first, look up second.

### Where this connects

The registers these modes use - the accumulator, the index register - come from 4.1, and the traces of the last unit are where the modes show their effect instruction by instruction.
