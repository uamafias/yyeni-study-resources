## Compression: why, which kind, and how

### Why files are compressed

Compression reduces a file's size, and a smaller file is cheaper to keep and quicker to move. Storage costs money by the byte, so a compressed archive fits more content on the same disk. A smaller file also takes less time to transmit, whether it is emailed, streamed or fetched from a website, because fewer bytes have to travel for the same content. The speed of the connection is set by the connection itself and does not change; the saving is in the time the smaller file takes. Where data is paid for by the megabyte, as with mobile connections in much of Namibia, compressing what is sent also cuts the bill. These are the three everyday reasons: less space, less waiting, less data paid for.

### Lossy and lossless compression

Compression differs by one question: can the original be rebuilt exactly? Lossy compression permanently removes some of the data, so the original cannot be rebuilt exactly; what comes back is a close copy, and the removed detail is gone for good. Lossless compression records the same data in fewer bits, so the original file is rebuilt exactly when it is needed. Each form earns its place. Lossy shrinks photographs and music far more, because it discards detail the eye and the ear are least sensitive to, and the results pass for the originals. Lossless is the only safe choice where every value matters: a spreadsheet of marks, a program file, a legal document, where one altered character is one too many.

### How the four file types are compressed

What the data is decides what a compression method can do with it. A bitmap with flat regions, such as a banner or a logo, compresses well with run-length encoding: the runs are of same-coloured pixels, and each run collapses into a colour and a count. A photograph compresses with a lossy method that discards fine detail the eye is least sensitive to; the sky's texture and the grass's speckle carry most of the file and little of the meaning. Sound compresses the same way by ear: the parts the ear is least sensitive to are discarded, and the file shrinks far beyond what lossless methods reach. A text file compresses with lossless methods, because every character carries meaning and none can be lost. A vector graphic is a short list of drawing objects already, so there is little repetition to squeeze and it usually travels as it is.

### Worked example: run-length encoding a row of a banner

Take one row of 16 pixels from a flat banner: ten pixels of colour 5, then three of colour 2, then three of colour 5. Stored as pixel codes at 8 bits each, the row takes 16 x 8 = 128 bits. Run-length encoding stores three pairs instead: (colour 5, run 10), (colour 2, run 3), (colour 5, run 3). At 8 bits for the colour and 4 bits for the count, each pair takes 12 bits, so the row takes 3 x 12 = 36 bits, less than a third of the original 128 bits. The encoding is lossless: reading the pairs back gives ten 5s, then three 2s, then three 5s, which is the original row exactly. Now change the data: a photograph's row, where the colour changes almost every pixel, gives runs of length one, so each pixel costs a 12-bit pair instead of an 8-bit code, and the 'compressed' row is larger than the original. RLE is a tool for flat regions, not for busy ones.

### Choosing a method for a given situation

Justifying a method means matching it to what the file is for and what its audience will notice. A photograph on a school website suits lossy compression: viewers judge the picture with their eyes, discarded fine detail passes unnoticed, and the smaller file takes less time to transmit to each visitor, because fewer bytes carry the same view while the connection's speed does not change. A marks spreadsheet sent to head office must come back number for number, so it needs lossless compression, whatever the smaller saving. The same file can need both answers at different times: a photographer keeps lossless originals in the archive and publishes lossy copies, because the archive must be able to rebuild exactly what the camera saw, while the website needs small files that load quickly.

### Common errors

Two slips recur. Describing an effect when a method was asked for: 'the quality gets worse and the file gets smaller' is what lossy compression does to the result, not a method; a method says what the compression does to the data, such as discarding detail the eye or ear is least sensitive to. The test: does the answer say what is done to the data? Then it is a method. Applying run-length encoding to the wrong thing: on a bitmap the runs are of same-coloured pixels, and on text the runs are of the same character. The test: name what repeats in this file, and encode runs of that.
