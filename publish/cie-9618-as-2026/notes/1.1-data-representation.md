## Number systems, prefixes and binary arithmetic

### Binary magnitudes and the two prefix families

Computers measure storage in bytes, and prefixes say how many. Decimal prefixes step by one thousand: one kilobyte (KB) is 1000 bytes, one megabyte is 1000 kilobytes, one gigabyte is 1000 megabytes, one terabyte is 1000 gigabytes. Binary prefixes step by 1024, which is two to the power of ten: one kibibyte (KiB) is 1024 bytes, one mebibyte (MiB) is 1024 kibibytes, one gibibyte is 1024 mebibytes, one tebibyte is 1024 gibibytes. The tell-tale is in the names: a prefix that contains the letters "bi" is a binary prefix, and its symbol carries a lower-case i (KiB against KB). These families count the same bytes differently, so a file reported as 2.0 MiB on one system can appear as about 2.1 MB on another, because a mebibyte holds more bytes than a megabyte: 1,048,576 against 1,000,000.

### Number systems and their place values

A number system's base sets its place values. Denary is base ten: from the right, its columns are worth 1, 10, 100 and so on. Binary is base two: each column is worth twice the one to its right, so an 8-bit pattern has columns worth 128, 64, 32, 16, 8, 4, 2, 1. Hexadecimal is base sixteen: columns are worth 1, 16, 256, and its sixteen digit values are written 0 to 9 then A to F, where A is 10 and F is 15. One hexadecimal digit corresponds to exactly four bits, which is what makes hexadecimal useful as a shorthand for binary. To convert denary to binary, take the largest place value that fits, subtract it and repeat. To convert binary to hexadecimal, split the bits into groups of four from the right and write each group as one hexadecimal digit. To convert hexadecimal to denary, multiply each digit by its place value and add: 3E is three sixteens and fourteen units, and 3 sixteens is 48, which with 14 more comes to 62.

### Binary Coded Decimal and two's complement

Two further representations handle particular jobs. Binary Coded Decimal (BCD) keeps the denary structure: each denary digit is stored as its own 4-bit group, so 46 is stored as 0100 0110, one group for the 4 and one for the 6, while pure binary stores the whole value as 0010 1110. No BCD group holds a value above 1001, because a denary digit runs from 0 to 9. Two's complement stores signed integers. The most significant bit carries a negative place value: in 8 bits it is worth -128 while the other bits keep their positive values, so a pattern beginning with 1 is negative and 8-bit two's complement runs from -128 to +127. One's complement, the stepping stone to it, flips every bit; two's complement flips every bit and adds 1. That is how -45 is found: 45 is 0010 1101, flipping gives 1101 0010, and adding 1 gives 1101 0011.

### Adding and subtracting in binary

Binary addition works column by column from the right. Zero and zero give 0; zero and one give 1; one and one give 0 with 1 carried into the next column; one and one with a carry give 1 with 1 carried. Subtraction avoids borrowing altogether: to subtract, add the two's complement of the number being taken away. Form it by flipping that number's bits and adding 1, then add, and discard any carry into a ninth bit. Overflow is the danger to watch. A register holds a fixed number of bits, and overflow occurs when a result needs more bits than the register holds. Two unsigned 8-bit values can sum past 255, or two positive two's complement values past 127; the register then keeps only the low eight bits and the stored value is wrong, so a system that adds must be able to notice the overflow.

### Worked example: one number, three forms

Take the denary number 202 and store it three ways. As an 8-bit unsigned binary integer: 202 takes a 128, leaving 74; a 64 leaves 10; an 8 leaves 2; a 2 finishes it, so the bits set are those columns and the pattern is 1100 1010. As hexadecimal, split the bits into fours from the right: 1100 is 12, written C, and 1010 is 10, written A, so 202 is CA in hexadecimal. Reading it back, C and A are 12 and 10; 12 sixteens is 192, and 192 with 10 more comes to 202. In BCD, each denary digit gets its own 4-bit group: 2 is 0010, 0 is 0000, 2 is 0010, so the BCD form is 0010 0000 0010, twelve bits for three digits. The same number, three different answers: the right form to use depends on the job at hand.

### Worked example: subtraction and overflow

Subtract 0010 0101 (37) from 0110 1100 (108) inside an 8-bit register. Flip the bits of 0010 0101 to get 1101 1010, add 1 to get 1101 1011, which is the two's complement form of -37. Now add: 0110 1100 + 1101 1011 = 1 0100 0111. The carry into a ninth bit is discarded, and the register holds 0100 0111, which is 71, the right answer, since 108 take away 37 is 71. Overflow shows up when two large values meet instead. Add the unsigned values 1100 0100 (196) and 0110 1101 (109): the true total is 305, which needs the nine bits 1 0011 0001, so an 8-bit register keeps 0011 0001 and reports 49. Before trusting an addition, ask whether the result still fits: a warehouse that received 305 bags would be told it holds 49.

### Common errors with prefixes and forms

Four slips recur. Mixing the prefix families: writing that a tebibyte is 1024 gigabytes joins a binary prefix to a decimal unit, when the binary chain runs tebibyte, gibibyte, mebibyte, kibibyte, each 1024 of the next below, so a tebibyte is 1024 gibibytes. Converting the whole number when BCD is asked for: 46 in BCD is 0100 0110, not the pure binary 0010 1110; count the digits and check that no group passes 1001. Reading two's complement as unsigned: 1001 1101 is -128 with 16, 8, 4 and 1, which comes to -99, not the +157 an unsigned reading gives; if the leftmost bit is 1, the value must come out negative. Writing hexadecimal digit values side by side: 7E is not "7 then 14" but seven sixteens and fourteen units; 7 sixteens is 112, which with 14 more is 126.

## BCD and hexadecimal in use, and character sets

### Where BCD is used

BCD earns its place wherever a device must show denary digits one at a time. A digital clock face, an electricity meter display and a calculator readout each show a number as separate digits, and because BCD stores each denary digit as its own 4-bit group, each display digit can be driven straight from its own group. A counter kept in pure binary has to be converted back into separate denary digits before it can be displayed, which takes extra logic. The cost of the convenience is storage: three denary digits take twelve bits in BCD, and the largest value they hold, 999, fits in ten pure binary bits.

### Where hexadecimal is used

Hexadecimal is the working shorthand for bit patterns. One hexadecimal digit stands for exactly four bits, so a long binary pattern becomes a quarter as many characters: the 16-bit pattern 1010 1111 0011 0110 is written AF36, and a mis-read digit is easier to spot in four characters than in sixteen. Memory addresses and error codes in a system's log are written in hexadecimal, machine code listings show each instruction's bytes in it, and colour codes on web pages give a colour's red, green and blue values as hexadecimal digit pairs. The hardware address of a network interface is written as six pairs of hexadecimal digits. The reason is the same each time: people who maintain systems read bit patterns, and hexadecimal lets them do it compactly with an exact mapping to the bits.

### Character sets: ASCII, extended ASCII and Unicode

Text is stored as numbers. A character set gives each character its own integer code, and the bits stored for a character are the binary form of that code. ASCII, the American Standard Code for Information Interchange, allocates 7 bits per character, so it defines 128 codes: enough for English letters in two cases, the digits 0 to 9, punctuation and some control characters. Extended ASCII uses all 8 bits of a byte, giving 256 codes and room for accented letters and drawing characters. Unicode is the character set built to cover the world's writing systems: because it allocates more bits per character, it can represent many more characters than ASCII's 128. The count of characters a set can represent is two to the power of its bits per character, so 7 bits give 128 codes and 8 bits give 256. Which set was used matters, because the same stored bits can decode to different characters under different sets, so a system reading character data needs to know the set that was used to write it.

### Worked example: storing a word in extended ASCII

When a form stores the word "HI" using extended ASCII, each character is stored as the 8-bit binary form of its code. H has the code 72 and I has the code 73. Finding the bits is a place-value job: 72 takes a 64 leaving 8, so H is 0100 1000; 73 takes the 64, the 8 and one more, so I is 0100 1001. The word is stored as the two bytes 0100 1000 0100 1001, and in hexadecimal the same two bytes are 48 49, which is how the codes appear in a system listing. Reading back reverses the route: the system splits the bits into bytes, reads each byte's value, 72 and 73, and looks up those codes in the set to show H then I. Nothing in the stored bits names the set: a reader that assumed a different set would show different characters for the same bytes.

### Common errors with character sets

The recurring error with character counts is taking the highest code for the number of characters. Extended ASCII's codes run from 0 to 255, which is 256 codes: the highest code is one less than the count, so "255 characters" is one short. The same arithmetic catches the bits-and-bytes slip: ASCII uses 7 bits per character, not 7 bytes, and 7 bytes would be 56 bits, eight times what a character needs. When a figure is quoted, divide by eight to see whether bytes are being described where bits are meant.
