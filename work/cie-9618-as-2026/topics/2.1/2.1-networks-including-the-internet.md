## Networks: why, what size, and which model

### Why computers are networked

Computers work alone until they are connected. A network is two or more computing devices joined so that they can communicate and share data and resources, and the connection changes what each machine can do. Files move between users directly instead of travelling on a storage device by hand. Hardware is shared: one printer serves a whole office, one file store holds the organisation's records, because each device on the network can reach them. Management becomes central: on a network with a server, backup runs once for everyone and security is administered in one place instead of machine by machine. Communication joins the list: two users work on one document across the network, a message reaches a colleague at the next desk, and a learner in the computer room submits work to a teacher's marking folder without leaving a chair. The devices that make a network - the switches, routers and access points met later in this topic - each do one job in moving data from a sender to a receiver, which is the infrastructure the sharing rests on. The benefits come with costs, and the costs are worth counting: a network needs hardware and cabling, someone to run it, and a fault in a shared device can stop many users at once, where a stand-alone machine fails alone.

### LAN and WAN

Networks come in two sizes. A local area network (LAN) covers one small site - one building, one campus - and is owned and managed by the organisation that uses it: the school's computer room, the office's floor. The devices on it are close together, and the links between them belong to the organisation. A wide area network (WAN) covers a large geographical area, joining sites across a country or the world, and it uses long-distance links leased from communication providers, because no organisation lays its own cable between towns. The internet is the largest example of a WAN: a network of networks spanning the globe, built from countless LANs joined by long-distance links. The two sizes meet in every organisation with branches: each branch runs its own LAN on its own site, and a WAN joins the LANs together. When a bank's Windhoek branch sends a record to Oshakati, the record travels inside a LAN, across a WAN, and inside another LAN, and each part of the journey uses the kind of network that fits that stretch. Ownership is the second mark of the difference: the bank's branch owns its own LAN's switches and cables, but nobody owns the whole internet - providers own stretches of it, and everyone's packets travel across one another's links, which is what paying a provider buys a place on.

### Client-server and peer-to-peer

Two models describe who does what on a networked system. In the client-server model, server computers provide services, files and resources, and client computers request and use them: the file server stores everyone's documents, the print server queues everyone's printing, and the client asks. Because the server holds the resources, it can control them: one account per user, one place for a backup, one point where security is set. In the peer-to-peer model there is no special server: each computer is equal, and any of them can share its own files, printer or connection with the others, acting as both client and server as needed. Each model earns its place. A client-server network suits organisations where central control matters - a school with learners' records, a firm with one file store - and it pays for it with the server's cost and the need to manage it. A peer-to-peer network suits a few machines in one room: nothing to buy beyond the machines and the cable, no manager needed, but each user is responsible for their own machine's shared data, and there is no central backup unless someone organises it. Justifying a model means matching it to the situation: count the machines, ask who is responsible for what, and ask whether the data is worth a server.

### Thin client and thick client

Clients themselves come in two forms. A thin client is a computer that depends on a server for processing and storage: it sends the user's requests over the network and displays the results, while the server does the work and holds the files. A thick client (also called a fat client) is a full computer: it runs its own applications locally, keeps its own files on its own storage, and needs no server to function. The differences reach into cost and security. Thin clients are cheap to buy and cheap to administer: software lives on the server and is updated once, data stays on the server, and a broken thin client is simply swapped. But a thin client without its server is a door with no house: it cannot work, and a network fault stops every thin client at once. Thick clients cost more and must each be maintained, updated and secured, and their data sits wherever their users have left it; in exchange they keep working without a server, they run demanding applications at their own pace, and a slow network does not throttle them.

### Worked example: choosing for a school office

A school office has five computers and one printer, and the office keeps the school's records. Which model, and which kind of client? Model first: records matter and must be backed up, and five users need controlled access to them, so the client-server model fits - one server holds the records, each staff account reaches them, backup runs on the server, and the printer hangs off the network for all five machines. Peer-to-peer would scatter the records over five machines with five owners and no central backup, which the records' importance rules out. Client kind second: the office's work is records and letters, not design or video, so the demands are light; thin clients keep all data on the server, which suits records that must not be lost, and one old machine that cannot run new software can still serve as a thin client because the server does the work. Had the office edited video, thick clients would have won the second choice, because rendering video over a network is slower than running it locally. Had the office been three friends sharing a flat's one printer, the whole reasoning would have flipped: three machines and nothing worth a server make peer-to-peer the sensible answer, which shows the justification runs from the situation, not from a favourite model.

## Topologies, the cloud, media and LAN hardware

### The four topologies

A network's topology is the arrangement in which its devices and links are connected, and four arrangements cover the field. In a bus topology, every device taps into one shared backbone cable; whatever is placed on the cable is seen by every device, and each takes what is addressed to it. In a star topology, every device connects by its own cable to one central device, usually a switch, and data reaches its destination by passing through that central device. In a mesh topology, each device is connected to several of the others, so data can travel by more than one route, and a full mesh goes further and connects every device to every other device. A hybrid topology combines the others - stars whose central devices sit on a shared backbone, or a mesh of core links with stars hanging off it. Drawing one is naming the boxes and the lines: a star is drawn as a hub with spokes, a bus as one line with devices hanging from it, a mesh as a web of lines. The packet's eye view matters as much as the picture: in a star a packet goes through the central device and out to its destination; in a bus it travels the backbone where every device sees it; in a mesh it may travel by several routes.

### How a topology behaves when things fail

Topology decides what fails when something fails. In a star, one broken cable strands exactly one device, and the rest keep working; the central device is the single point of failure, and its death stops the whole network. In a bus, one break in the backbone can stop every device, because the shared cable is the whole network. In a mesh, a broken link merely removes one route, and traffic moves to the remaining routes, which is why demanding networks use meshes despite the cost, a cost that grows quickly because each new device needs links to several others. The test that separates star from mesh: remove the central device - in a star every link fails, because every link ends there; in a mesh the others still connect. That test is also the justification: choose the topology whose failures the situation can afford, because the failure behaviour, not the drawing, is what the organisation lives with.

### Cloud computing, public and private

Cloud computing provides storage, software and processing as services over the internet, so an organisation uses a provider's infrastructure instead of buying and running its own. The immediate effect is on cost: the organisation stops buying servers and paying a room to keep them in, and starts paying for what it uses, month by month. The second effect is on reach: files and applications live on the internet, so work happens anywhere with an internet connection. The cloud comes in public and private forms, and the words say who the service is for, not who can read a user's data. A public cloud is provided for anyone to buy and use, and its infrastructure is shared among many customers, which is where its cheapness comes from. A private cloud is provided for one organisation alone, and its infrastructure is not shared with other customers, which is where its control comes from. Who can read particular data is a question of accounts and permissions, which both kinds still need. The drawbacks sit beside the benefits: a cloud user depends on the connection and on the provider, and the data lives on infrastructure the organisation does not own, so decisions about records with duties attached - patient records, for instance - weigh the private kind.

### Wired and wireless media

The links themselves are media, and each carries data its own way. Copper cable carries electrical signals: it is cheap and everywhere, but it picks up electrical interference, and its signals weaken over distance, so runs are kept short. Fibre-optic cable carries pulses of light along glass: light resists electrical interference, carries data further without repeating, and runs faster than copper, at a higher price and with more care in laying. Radio - including wi-fi - carries data through the air, so devices move freely and no cables are laid, but the signal weakens with distance, is affected by walls, and can be received by anyone within range. Microwave links carry data in straight line-of-sight beams between dish antennas, joining buildings or towns where no cable is laid. Satellites relay data between ground stations over very large areas, which serves remote places at the price of the long distance the signal travels. The choice between wired and wireless is a choice of what the situation values: wired connections are generally faster and more stable but need cable laid to each device; wireless connections are convenient and mobile, but their performance varies with distance, walls and interference.

### The hardware that supports a LAN

A LAN's parts each do one job. The switch connects wired devices and sends each arriving packet only to the port of the device it is addressed to, so two machines talking do not slow the others. A server provides the shared services - file storage, printing, logon - that a client-server network runs on. A network interface card (NIC) is the circuit a device uses to join a wired network, and it carries the device's unique MAC address, which is fixed in the hardware; a wireless NIC (WNIC) does the same job by radio. One caution on addresses: the NIC carries the MAC address, and the device's IP address is assigned by the network it joins, not built into the card. A wireless access point (WAP) lets wireless devices join the LAN by radio. A bridge joins two network segments so they behave as one network. A repeater takes a weakening signal and re-transmits it stronger, so a LAN reaches beyond one cable's length. Cables are hardware too: the copper or fibre the wired parts hang from.

### Worked example: a packet crosses a star

In a youth centre's star LAN, the reception computer sends a form to the office computer. The reception machine's NIC places the form's packets on its cable to the switch. The switch reads each packet's destination address and sends it out of the office computer's port only - the other twenty devices never see it. The office machine's NIC takes the packets and the office software reassembles the form. If the link to the switch from the games room breaks, exactly one thing fails: the games room. If the switch itself fails, everything stops, which is the star's bargain: simple, one device per cable, one fatal point. A mesh among all the centre's machines would keep the games room connected after a break, but the centre would run dozens of links for twenty machines, which is why centres buy stars.

### Common errors

Three slips recur here. Drawing a mesh and calling it a star: a star connects every device to one central device, a mesh connects each device to several others, and the test is to remove the central device - a star loses every link, a mesh keeps its others. Believing the kind of cloud says who can read the data: public and private describe who the service is provided for and who shares the infrastructure, not access to files. Believing the NIC gives the device its IP address: the card carries the MAC address, fixed in the hardware, while the IP address is assigned by the network - which address is built into the card is the test.

## Routers, Ethernet, bit streaming and the web

### What a router does

A router connects networks together. A switch moves packets between devices on the one network it serves; a router stands between networks, and its job is to forward each packet from one network toward another, choosing the packet's next step by the destination IP address it carries. On the internet, this is the whole mechanism of delivery: a packet leaves the sender's network through a router, is passed from router to router, each reading the destination address and choosing the next network in that direction, until a router on the destination's own network delivers the packet to the device. Two properties follow. Packets of one message may travel different routes, because each router chooses for itself, so the parts of one photo can arrive by different paths and be reassembled at the far end. And the sender needs no map: the sender hands the packet to its own router, and every step after that is chosen by the router that holds the packet. This is why a school LAN that must reach the internet needs a router and not only a switch - the LAN and the internet are different networks, and joining networks is the router's job, not the switch's.

### Ethernet and how collisions are handled

Ethernet is the family of standards a wired LAN most often runs on: it defines the cables, the connectors and the rules devices follow to place data on the network. The rule that matters here is CSMA/CD - Carrier Sense Multiple Access with Collision Detection. Take it in order, as its name runs. Carrier sense: before a device transmits, it listens to the cable, and it transmits only when it senses no signal already on it. Multiple access: every device on the cable shares it, and any of them may transmit when it finds the cable free. Collision detection: transmitting devices keep listening while they send; if two devices found the cable free at the same moment and transmitted together, their signals overlap and garble on the cable, and each detects that what is on the cable is not what it sent. What happens next closes the loop: each colliding device stops, sends a short jamming signal so every other transmitter stops too, then waits a random time - different for each device - before sensing the cable and trying again. The different random waits are what break the deadlock: the two devices no longer choose the same moment, so the retry goes through.

### Bit streaming

Downloading waits; streaming does not. Bit streaming sends multimedia content as a continuous stream of bits, and the player starts playing from the first bits that arrive, before the whole file has come. Two forms cover most use. Real-time streaming presents an event as it happens: the match, the meeting, the ceremony - the viewer sees what is happening now, or as close to now as the stream's delay allows. On-demand streaming starts whenever the user chooses: the film begins when the play button is pressed, because the file waits on a server, ready to stream. The two forms differ in who sets the clock: in real-time streaming the event sets it, and joining late means seeing the event from the moment of joining; in on-demand streaming the user sets it, pausing and resuming as they please, because the server streams from wherever the player asks. Both forms live on one number: the bit rate. The player consumes bits at the content's own rate, and the connection delivers bits at the connection's rate. If the connection's bit rate is at least the content's, playback runs smooth. If the connection delivers more slowly than the player consumes, the player's store of bits runs out, playback pauses, and the buffering mark appears until enough bits have arrived - and if the gap is large, this repeats to the end, which is the experience the word 'buffering' has come to stand for. The remedies follow from the cause: a lower-bit-rate stream that fits the connection, or a faster connection - the film's size is not the number that decides.

### The internet and the World Wide Web

The two words are used as if they meant one thing, and they do not. The internet is the infrastructure: the cables, the routers, the connected networks - a global network of networks that carries whatever is sent on it. The World Wide Web is a service that runs on that infrastructure: a collection of pages of content, linked to each other, stored on servers, and fetched by browsers. A web page cannot travel without the internet's cables and routers, because that infrastructure moves every packet; equally, the internet carries far more than the web - email, file transfers, streaming services - so the web is one service among several on the same wires. The everyday complaint 'the web is down' usually means one service failed while the infrastructure still carries the others, which the distinction explains. Resources on the web are named by URLs, which 2.1.4 unpacks; fetching them is the work a browser does.

### Worked example: a film on a thin connection

A teacher wants to show a 20-minute documentary in a village classroom whose connection delivers reliably at 1 megabit per second. The documentary's standard stream plays at 2 megabits per second. Started at that rate, the player's buffer drains: the connection delivers 1 megabit each second while the player consumes 2, so after a minute of playing, a minute of stream is missing, playback stops, the buffering mark appears, and the cycle repeats - the class watches a slideshow of pauses. The lower-quality stream at 0.8 megabits per second fits: the connection delivers faster than the player consumes, the buffer grows while playing, and the film runs to the end. What changed was not the film's size but its rate: streaming is decided by bits per second on both sides, which is why the choice of stream, not the choice of file, is the classroom's lever.

### Common errors

Two slips recur. Sending data in 'packages': the unit of data on a network is a packet - a header carrying addresses and a sequence number, and a payload - and 'package' is not the technical term, so an answer that uses it has not named what is addressed and routed. Confusing the internet with the web: the internet is the infrastructure of cables and routers, the web is a service of linked pages that runs on it, and the test is to ask which one carries the other.

## The internet's hardware, IP addresses and URLs

### Hardware that supports the internet

A household or a small organisation does not own the internet's cables; it rents a way in. A modem converts between the digital signals a computer network uses and the form the link carries, so a household can reach the internet over a telephone line or a cellular connection. The PSTN - the public switched telephone network, the ordinary telephone system - can carry data as well as voice, over lines built for voice, which makes it slow but almost everywhere available. A dedicated line is a permanent link reserved for data between two points: a business pays for a line that stays up around the clock, carries no other traffic, and needs no call to be set up. A cell phone network connects devices by radio through masts, giving access wherever the provider's coverage reaches - the way in for much of rural Namibia, where fixed lines do not go. Between the household's way in and the internet's core sit the providers' networks and the routers of 2.1.3; the whole is the network of networks the earlier units described.

### IP addresses: IPv4, IPv6, public and private

Every device on a network carries an IP address that identifies it there, so packets can be delivered to it - the address is the postal address of the networked world. IPv4 writes the address as four denary numbers separated by full stops, each 0 to 255: 192.168.1.20. Its 32 bits give about 4.3 thousand million combinations, and the world's connected devices outnumbered them, which is why IPv6 was introduced: its 128 bits write the address as eight groups of four hexadecimal digits separated by colons, and its range is vastly larger. Addresses come in public and private forms, and they are different things. A public IP address is unique across the internet, assigned by a provider, and any device can send to it from anywhere. A private IP address is used inside a local network, where it identifies the device to its own LAN; it is not unique on the internet, and a device on the far side of the world cannot reach it directly. A LAN's router holds the public address and speaks for the LAN outside. Subnetting rounds out the set of ideas: one network's address range is split into smaller networks, each with its own range, which keeps traffic local and makes large networks manageable.

### How a URL locates a resource

A URL - Uniform Resource Locator - names one resource on the web, and its parts each do one job. Take http://www.omatele.co.na/fees.htm apart. The scheme, http, names how the resource is fetched. The domain name, www.omatele.co.na, names the server that holds it - the machine the request must reach. The file path, /fees.htm, names the file on that server - the resource itself. Reading the URL in order answers three questions in order: how to ask, whom to ask, and for what. A browser put to work on one reads it exactly that way: it takes the domain name, finds that server's IP address, sends a request for the file at the path using the scheme's way of asking, and displays what returns. The URL is the web's address on paper; the fetch is the machinery that turns it into packets.

### Worked example: one fetch, step by step

A learner types http://www.dune-college.edu.na/subjects/science.htm into a browser. First the browser reads the scheme, http, so it knows how it will ask. Second it reads the domain name, www.dune-college.edu.na, and finds the college server's IP address. Third it sends a request for the file at the path /subjects/science.htm to that address. The college's server receives the request, finds the file, and sends the page back; the browser reads what returns and shows the subject page. Every web visit runs this loop: scheme for the how, domain for the where, path for the what - and the infrastructure of the last three units carries each request and each page as packets across the internet.

### Common errors

Three slips recur. Treating public and private IP addresses as one kind: a private address works inside its own LAN and is not unique on the internet, whereas a public address is unique across the internet and reachable from anywhere - the test is whether a device on the other side of the world can reach the address directly. Miswriting IPv6: eight groups of four hexadecimal digits, separated by colons, with a double colon standing in for a run of zero groups - count the groups and check the separator. And calling the NIC or WAP the giver of IP addresses: the card carries the MAC address fixed in the hardware; the IP address is assigned by the network the device joins.
